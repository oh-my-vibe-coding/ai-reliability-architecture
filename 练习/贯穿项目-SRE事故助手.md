# 第 20 章 · 贯穿项目：SRE 事故助手

> 所属：第四部分 · 训练与落地  ·  [← 返回目录](../README.md)

事故助手收到一段告警，找到了相关 Runbook，并给出三步排查建议。这只证明正常路径能够运行。若文档夹带一条"把日志发到这个地址"的指令，工具会不会照做？检索结果过期时，回答会不会仍然带着看似可信的引用？取消任务后，重试是否还在计费？

贯穿项目让这些问题在同一个系统里逐步显现。Unit 0-5 分别增加功能、边界、观测和验证，最后用 Capstone 审查证据。

**本章是一份需要读者实现的训练规格。** 下文的项目目录和文件名是建议结构；本书提供独立的[参考代码](../代码/README.md)，没有随本章交付一套已经完成、验收或生产就绪的事故助手。

---

## 1 · 项目目标与使用边界

构建一个面向受控 SRE 场景的助手：输入事故描述、样例日志或指标摘要，检索获准使用的 Runbook / Postmortem，调用有明确范围的只读工具，生成带来源与不确定项的结构化排查建议。

练习的核心链路是：

```text
任务与身份 → 检索和工具 → 有依据的建议 → Trace 与指标
                  ↑                    ↓
               权限和预算          评估、复核与改进
```

主线不执行生产变更。只读工具同样可能泄露敏感数据、耗尽资源或访问越界，因此必须由可信执行器检查调用身份、参数、数据范围和预算。模型生成的工具名、路径或"用户已批准"文字都不能替代授权。

建议先在隔离的训练目录或容器中，用公开、合成或明确获准的数据运行。进入真实环境之前，另行完成数据、凭据、网络和操作范围的评审。训练进度本身不授予生产权限。

## 2 · 最小形态与起步数据

起步可以只有一个 CLI、文件检索、两个样例工具和 JSONL 运行记录。以后需要共享访问、并发或持久化时，再增加服务和存储组件。

| 组件 | 最小职责 | 何时需要扩展 |
|---|---|---|
| 模型适配器 | 统一调用、工具结果、错误和用量记录 | 更换后端、处理流式与限流时 |
| 检索 | 返回来源、片段和文档版本 | 数据增长、权限过滤或需要更好召回时 |
| 工具执行器 | 独立检查身份、参数、范围与资源限制 | 接入真实只读数据源时 |
| Trace | 串联任务、步骤、版本、结果及失败原因 | 并发、查询与取证需求增加时 |
| Eval | 复用任务定义和判定标准输出报告 | 增加场景、评判器或发布门禁时 |
| 指标与预算 | 记录耗时、调用、费用及停止原因 | 多任务共享额度与容量时 |

模型可以来自获准的托管服务或本地端点；检索可以从关键词起步，再与向量检索比较。更换技术栈要重新验证能力与边界，接口兼容不等于行为一致。

### 离线起步也可以，但结论要对应实验

没有模型权限时，先用固定的工具调用和模型返回样例测试流程、权限拒绝、超时和记录格式。它能验证控制逻辑，不能测出真实模型的回答质量、token 用量或推理延迟。接入真实后端后，补跑相关用例。

拥有自管算力时，可接入[贯穿部署线](贯穿部署-H20推理服务.md)的端点。服务部署与容量验证另计时间，不是完成主线的前提。

### 样本数量服从覆盖目标

起步可准备少量 Runbook 和约 5 个冒烟问题，先证明链路能运行。之后根据任务类型、失败模式和数据来源扩展。20 份文档或 30 条评估样本可以是练习规模，**不能作为充分覆盖或生产准入的保证**。

至少保留一组后续检验使用的独立样本，避免一边反复调 Prompt，一边把同一批题的分数当成泛化表现。拆分时留意同一事故、相邻日志和同一文档改写造成的泄漏。

## 3 · 从第一天保留的案例与证据

在增加功能前，先写预期行为。以下是需要实现和验证的案例类型，不表示这些控制已经存在。

| 案例 | 预期行为 | 要核对的证据 |
|---|---|---|
| 已有来源支持的告警 | 给出有依据的排查建议 | 引用定位正确，支持对应结论 |
| 文档中没有答案 | 说明缺口或请求补充信息 | 没有编造来源、指标或执行结果 |
| 用户请求无权查看的日志 | 在执行器处拒绝 | 受限文件未读取，拒绝原因可定位 |
| 检索内容要求外传数据 | 将内容视为不可信数据，阻断未授权动作 | 未发生出站发送，策略版本和尝试已记录 |
| 工具超时、取消或预算耗尽 | 按定义停止，并记录在途状态 | 无越界继续调用，资源及费用可核对 |
| 相邻租户请求相同问题 | 不共享未经授权的检索或缓存内容 | 身份、ACL 和缓存键隔离测试 |

每条用例都应有 ID、数据来源、身份与策略、预期行为、实际结果、运行版本和判定依据。可以先记录人工结果，再自动化；不能把未运行的测试标为通过。

**已知的关键越权或外传路径必须阻断，才能在该范围继续开放。** 一个 payload 被拦住，不抵消另一个关键 payload 成功。通过现有测试也只说明覆盖范围内的结果，不能证明所有攻击都已消除。

## 5 · 每个 Unit 的项目产出

### Unit 0 · 启动最小系统（~2 周）

新增检索、Agent 循环和少量只读样例工具。建议文件为 `app/ingest.py`、`app/retrieve.py`、`app/agent.py`、`app/tools.py`，并在项目 README 写清运行环境、命令和限制。

初始工具优先读取训练目录中的固定样例，不连接主机任意文件或生产接口。设置任务超时、步数及调用限制；若调用付费服务，还要设置费用控制并检查用量。

**验收证据**：

- [ ] 从干净的训练环境能按说明复现 ingest 和 query，依赖与配置有记录。
- [ ] 冒烟用例逐条报告结果，区分有依据的回答、错误和证据不足时的停止。
- [ ] 引用能定位到文档版本和片段，不能只检查链接是否存在。
- [ ] 至少验证越界访问拒绝，以及超时或预算耗尽时的结束行为。
- [ ] 已说明使用的是真实模型还是固定样例后端，结论与其一致。

少量题答对多数，只能发现明显故障。关键权限失败不能用回答通过率抵消。

### Unit 1 · 权限与安全（~4 周）

新增 `docs/threat-model.md`、权限配置和攻击回归用例。威胁模型覆盖用户输入、文档、日志、工具结果及它们可能到达的接收方；用致命三角识别特定的外传条件，不把它当成全部安全问题。

策略应由执行器结合可信身份检查。需要确认的动作，要把批准绑定到具体操作、参数和范围，不能接受模型自称获得了确认。路径限制需考虑目录穿越、符号链接和间接读取；网络控制需覆盖实际可用的出口。

**验收证据**：

- [ ] 每条攻击记录入口、目标、可达路径、控制点和结果。
- [ ] 测试覆盖允许与禁止操作，并核对实际文件、网络或接口访问；不能只看错误消息。
- [ ] 现有范围内发现的关键越权和外传路径已修复或通过缩小范围关闭，并完成回归。
- [ ] 基础设施与应用执行器的限制可独立于模型意愿执行，剩余风险和未测面明确。

### Unit 2 · Trace + Eval + Flywheel（~4 周）

新增 Trace schema、评估集、判定标准和失败队列。用任务与步骤 ID 关联模型、Prompt、工具、检索索引、文档和策略版本；记录失败、取消、截断、停止原因及用量缺失，不能只保存成功回答。

Trace 原始材料进入评估集前，需要授权检查、去标识、抽样、标注和复核。可回放也要区分使用旧工具结果的离线重放，与重新调用工具的实验；后者的数据和环境可能已变。

**验收证据**：

- [ ] 选一个失败任务，能够定位当时版本和证据；无法重现的部分明确记录。
- [ ] 评估覆盖当前任务分桶和关键负向案例，报告样本数、分母、失败类型与适用范围。
- [ ] 若用模型 judge，以人工复核的正反例检查误判，并按场景报告分歧；换一家模型不能自动保证独立可靠。
- [ ] 失败样本经人工确认后更新标签，记录来源和版本；保留独立检验数据。
- [ ] Trace 的内容、访问和保留期符合数据边界，评估副本不会绕过它们。

### Unit 3 · 可靠性工程（~4 周）

新增 `docs/slo.md`、指标和预算控制，以及发布 / 回滚决策树。可先用本地结构化报告，不必为练习搭建完整监控平台，但定义的指标必须有实际测量。

**验收证据**：

- [ ] 每个 SLI 有对象、好坏事件、分母、窗口、测量边界和缺失数据处理规则。
- [ ] 分开记录首包、完整任务耗时和成功完成率；超时、取消、流式中断不会消失。
- [ ] 在记录了环境与负载的条件下，测试限流、排队、超时、取消及在途任务，说明容量结论的边界。
- [ ] 比较缓存开关时保持可比任务，检查命中收益、错误复用、权限隔离和版本失效。
- [ ] 费用估算能够与用量或账单核对；预算预留、停止和释放经过失败路径测试。
- [ ] 灰度 / 回滚规则有测量依据、观察窗口、责任人和数据不足时的动作，并完成一次恢复演练。

离线质量样本、在线可用性和费用分别报告，不能平均成一个总分。回滚若涉及索引或状态迁移，还需验证数据同步和读写版本；仅恢复配置不一定恢复系统状态。

### Unit 4 · 复合可靠性数学（~3 周）

画出真实的步骤、分支、重试和停止点。对一条固定必经路径，可以用条件成功率的链式关系分析：每一步的概率都应说明其前提和样本。不同分支、循环及相关错误不能随意套用边际成功率相乘。

选择一个有明确目标的 verifier 或 gate 做比较。**不规定必须加两处，也不预设它一定提高完成率。** 已有的确定性校验、约束工具接口或直接缩短路径，可能比增加模型评判更适合。

**验收证据**：

- [ ] 步骤估计有样本和判定依据；不足以估计的项标为未知，没有为填表编造概率。
- [ ] 在可比任务、版本和预算下，比较无 gate 与有 gate 的成功完成、错误放行、安全停止、延迟和成本。
- [ ] 对本来正确与本来错误的候选分别核实 gate 的接受 / 拒绝情况，写清每个比例的条件分母。
- [ ] 检查重试是否重复同类错误，是否绕过预算、权限或停止条件。
- [ ] 结论说明收益、代价和不确定性；效果不好时允许删除或替换 gate。

### Unit 5 · 数值底座 + 本地部署（可选）（~2 周）

新增数值级 Runbook，包含触发信号、分层诊断、实验命令、环境和结果。可以选一个 toy softmax / 精度实验；有条件时，再比较本地模型或量化配置。

**验收证据**：

- [ ] 至少一个受控实验可以复现，记录输入、软件与硬件、精度设置和观察结果。
- [ ] Runbook 区分输入、采样、服务实现、数值设置和编译 / 内核问题，标明每层的排除依据。
- [ ] 若比较模型或配置，使用可比任务和质量标准；同时记录延迟、容量和成本口径。
- [ ] toy、较小本地模型和目标生产环境的结论边界明确；未做目标环境实验就不声称已验证。

### Capstone · AI 可靠性架构评审包（~1 周起）

以项目为对象进入[第 21 章](Capstone-AI生产架构评审包.md)，将已有材料连接到 15 节评审问题。组织、契约、交接和生命周期等内容，未必已经包含在代码单元里，需要补充实际依据，或明确这是训练场景的假设。

评审发现缺口时，补实验、修代码或缩小开放范围，再更新文档。最终成果包括运行说明、证据索引、评审决定和未完成行动项；不能仅凭目录齐全宣布进入维护期。

## Mastery Gate

训练完成的标准，是能够展示并解释以下证据：

- [ ] 运行环境、数据来源和后端类型明确，正常与失败用例可复现。
- [ ] 回答的来源支持性、证据不足处理和已知质量缺口经过核查。
- [ ] 可信执行器实施权限及资源限制，已知关键攻击路径已阻断并回归。
- [ ] Trace 与版本关联完整，失败回流有授权、标注和复核流程。
- [ ] 评估标准、样本与判定误差可解释，结论不超出覆盖范围。
- [ ] SLI 有实际测量，预算与停止条件经过故障验证，恢复流程演练过。
- [ ] 步骤与 gate 的比较同时报告成功、错误放行、安全停止和代价。
- [ ] Runbook 有可复现实验，Capstone 明确使用范围、未知项及责任。

满足这些条件，说明你完成了相应范围的工程训练。生产准入还需要目标环境、业务风险、权限、容量、运维及合同条件的独立评审；训练项目不等同于实际生产事故经历。

## 可选支线 · 日志分类小模型 / LoRA 微调

当一个稳定的窄任务值得单独优化时，可以比较规则、传统分类器、小模型、Prompt、检索增强和微调。例如，将事故归入有明确定义的类别，或为主线选择候选 Runbook。

决策依据应是目标任务、质量要求、数据和全生命周期成本，而非"主线做完就该微调"。LoRA 是微调方法之一，不是所有分类问题的默认答案。

开展前至少准备：

- 当前基线，以及各类别误判、漏判和未知类的处理方式。
- 来源合规、标签标准一致的数据；按事故或时间等合适方式拆分，防止泄漏。
- 训练前保留的独立评估集，必要时包含分布变化场景。
- 训练、服务、监控、更新和退出的成本与负责人。
- 分类不确定或漂移时的降级方案；若退回 LLM，要另验质量、权限和容量。

数据量没有统一的 1000 条门槛。用类别覆盖、标签质量和学习曲线判断继续标注或训练是否有收益。若边界仍在频繁变化、关键类别数据不足或无人维护，先处理这些问题，再决定是否训练。

支线接入主线后，要重新跑端到端用例。分类分数上升，不保证下游排查建议更可靠。

## 关于真实数据

优先使用可以合法处理和发布的合成材料或公开资料，并保留来源及许可说明。公开可访问不代表可以不受限制地复制、训练或再发布。

使用公司或客户材料前，确认组织授权、允许的接收方和用途。脱敏是处理措施，不能代替授权；仅替换服务名和 IP 也未必消除身份、拓扑、凭据或商业信息。还要检查文档元数据、工具返回、Trace、评估副本和错误日志。

保持有用的结构时，可以合成故障时间线、指标和日志，明确标记为模拟。若脱敏改变了任务难度或答案，也要相应调整评估结论。

## 常见问题

### Q1：工作中暂时没有 AI 系统，值得做吗？

若你需要理解模型依赖、工具权限和质量测量，这个项目提供了可控的训练场景。先做最小链路，根据岗位目标决定投入，不需要用未来一定采用 LLM 的预测来证明它的价值。

### Q2：不能调用外部模型，能做吗？

可以使用获准的本地模型，或先用固定样例验证控制链路。选择本地后端时测试工具协议、输出约束和资源条件；使用固定样例时，明确真实模型质量与推理性能尚未验证。

### Q3：时间少，怎样裁剪？

缩小功能：只选一类事故、一个数据源、一个工具和一个模型；可先用关键词检索、确定性检查和本地报告，推迟向量服务、多供应商、模型 judge 和自管部署。

保留数据授权、可信执行器限制、关键攻击与失败测试、基础 Trace、实际测量和人工可核查的评估。没有 judge 就用清楚的规则和人工标签，不必声称完成了 judge 校准；没有实现 verifier，就报告基线和未做比较的原因。

裁剪后的项目可以是一项完整的小练习，但不等于完成全部 Unit 或完整 Mastery Gate。按实际范围估时，不承诺统一的六周速成结果。

### Q4：可以公开项目吗？

可以公开你有权发布的代码、合成样本和证据摘要。发布前核对代码、数据、依赖许可和提交历史，检查密钥、Trace 与内部文档。展示时明确模拟环境、测试覆盖和已知缺口，让他人能够复现你实际证明的部分。

本项目的价值在于留下连续证据：从一次能运行的调用，走到能够解释质量、权限、费用和恢复边界的系统。遇到问题时按需查[深入专题](../README.md#深入专题)，用[模板库](../附录/E-模板库.md)整理证据，再交给 Capstone 审查。
