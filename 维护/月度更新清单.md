# 月度更新清单

> [← 维护系统](README.md)

> [!NOTE]
> **每月安排一次扫描**，同时看事实、工作范式与核心论断的变化信号。
>
> 15-20 分钟可以作为快速分诊起点；来源核验、实验和修订另计时间。

---

## 范围与时间

先看高影响依赖及待办，再扫描三类变化。原有的型号、价格、工具与链接检查继续保留；本月还应记录工作方式或关键前提是否出现值得核实的变化。

查不到原始证据时标记未核验。完成一次扫描不要求一定修改 2-3 章、提交代码或发布新版本；剩余调研、实验和跨章修订单独排期。

---

## 阅读约定 · 页面探索一律走 Jina Reader 代理

> [!IMPORTANT]
> 本清单里所有需要"打开页面/抓页面内容"的动作，**统一通过 [Jina AI Reader](https://jina.ai/reader/) 代理读取**——不要直接抓原站。
>
> **代理格式**：`https://r.jina.ai/<原始URL>`
> **搜索格式**（可选）：`https://s.jina.ai/<查询词>`
>
> **为什么**：
>
> - 原站经常上 Cloudflare / WAF / JS 渲染，`curl` 和 `WebFetch` 取不到正文；Jina Reader 已统一把页面渲染并转成 LLM 友好的 markdown。
> - 代理返回稳定的纯文本，便于人眼快读和 diff，也便于喂给 AI 做对比。
> - 失效或限流时再退到 `archive.org` 或厂商官方 API（`gh`/RSS/`arXiv`）。
>
> **用法**：浏览器里可以直接打开 `https://r.jina.ai/https://example.com/path`；命令行里 `curl -s https://r.jina.ai/https://example.com/path` 即得 markdown。下文每条 URL 都已按此约定改写。

## Part A · 快照数据更新（每月必做）

### A1 · 模型榜单（深入 03）

- [ ] 打开 https://r.jina.ai/https://arena.ai/leaderboard
- [ ] 记录当前 Overall Top 10 的前 3 名（只要前 3 变了就更新）
- [ ] 记录 Coding Top 5
- [ ] 如有**新模型进榜单**或**分差 >30**，更新 深入 03 · §3.11

- [ ] 打开 https://r.jina.ai/https://openrouter.ai/rankings
- [ ] 记录时间窗、页面数据日期和免费档，看 Top 10 变化（无付费筛选时不声称付费榜）
- [ ] 更新 深入 03 · §1.5 的表格

- [ ] 打开 https://r.jina.ai/https://www.swebench.com/verified.html
- [ ] 看 Verified Top 5 有无变化
- [ ] 更新 深入 03 · §3.11（SWE-bench 表）

### A2 · 厂商定价 / 新模型（深入 03）

对每家厂商 docs 查一眼（1 分钟/家，走 Jina Reader 代理）：

- [ ] Anthropic: https://r.jina.ai/https://platform.claude.com/docs/en/docs/about-claude/models
- [ ] OpenAI: https://r.jina.ai/https://platform.openai.com/docs/models
- [ ] Google: https://r.jina.ai/https://ai.google.dev/gemini-api/docs/models
- [ ] DeepSeek: https://r.jina.ai/https://api-docs.deepseek.com/
- [ ] 中国系（Moonshot / MiniMax / 智谱 / 腾讯）跑个 `https://s.jina.ai/<query>` 看有无大版本

**发现新模型** → 核实来源与使用条件，判断是否影响本书任务、选型或既有建议；有影响时再更新定义源，不把产品列表无限扩张。

### A2b · 三大模型系列口径（深入 12）

- [ ] Claude：Opus / Sonnet / Haiku 命名、context、extended thinking、tool use、prompt caching 是否有变化
- [ ] OpenAI：GPT / mini / nano / reasoning / Codex 命名、Responses API、structured outputs、reasoning effort 是否有变化
- [ ] Gemini：Pro / Flash / Flash-Lite / Live 命名、long context、thinking、function calling 是否有变化
- [ ] 如有变化，同步更新 [深入 12](../深入/12-Claude-GPT-Gemini三大模型系列使用指南.md)、[附录 C](../附录/C-术语表.md)、[附录 D](../附录/D-厂商官方学习资源.md)

### A2c · Batch API 价格 + Embedding 模型（深入 13 / 16）

- [ ] Anthropic / OpenAI / Gemini Developer / Vertex Batch 的价格、配额与完成契约是否变（分别核验接口，不把处理目标当 SLA；深入 13 §2.1）
- [ ] DeepSeek 折扣时段是否调整（含节假日例外）、旧 alias 是否被重新路由
- [ ] Embedding 模型榜单：MTEB 是否有新前列模型；bge / nomic / voyage / cohere 价格变化（深入 16 §2）

### A3 · 工具生态（深入 03）

- [ ] `gh repo view anthropics/claude-code` 查 star 数 + 最新 release（`gh` 走官方 API，不经代理）
- [ ] 同样对 openai/codex, google-gemini/gemini-cli, anomalyco/opencode, cline/cline
- [ ] 多产品仓库分别核验 CLI / 扩展 / Desktop 轨道，不直接把 `releases/latest` 当扩展版本
- [ ] 各工具官网/博客若需要看正文，统一走 `https://r.jina.ai/<原 URL>`
- [ ] 有重大新工具出现 → 记录它改变的工作和约束，核实后决定是否进入表格或方法审查

### A4 · 附录 B 链接存活性

- [ ] 抽样 10 个 参考文献 的链接是否仍然有效（同时检查代理 HTTP 状态和正文标题 / 错误——200 也可能包着上游 403 challenge，不能只按状态码判活）
- [ ] 失效的链接 → 在附录 B 标注 `[broken]` 或找替代（替代源也优先用代理验证一次能读到正文）

### A5 · 复习系统校对

- [ ] 打开 [核心概念卡](../复习/核心概念卡.md) 与 [anki-import.csv](../复习/anki-import.csv)
- [ ] 检查涉及 **模型命名、价格、context、厂商分层** 的卡片是否过时（Gemini Pro/Flash 命名、Claude Opus/Sonnet 当前旗舰、GPT 价格、tokenizer 代际差异）
- [ ] 涉及 **快变事实** 的卡片要么更新、要么改写成"问机制不问数字"
- [ ] **核心概念卡和 csv 必须同步**：在概念卡里改了任何 Q/A，对应的 csv 行也要同步。否则 Anki 用户的卡片和 markdown 不一致
- [ ] 方法或理念被限定、改写或撤回时，检查训练验收和概念题是否仍在强化旧结论

### B5 · 工作范式与理念信号（每月扫描）

按[范式与理念审查](范式与理念审查.md)检查候选变化：

- [ ] 任务委托、人机协作、上下文与记忆、长任务恢复或验证方式有无变化信号？
- [ ] 它改变了哪项实际工作？是新能力声明、可复现结果，还是已有工作记录？

## Part C · 收尾（每月必做）

### C1 · 更新 CHANGELOG

先在 [CHANGELOG · Unreleased](CHANGELOG.md#未发布unreleased) 区分已完成修订与待验证发现。决定发布后，再按[更新模板](更新模板.md)整理版本条目：

```markdown
## vX.Y.Z — YYYY-MM-DD

### 事实与实现
- [已核实的快照、兼容或链接修订]

### 工作方法与核心论断
- [原主张、新证据、适用范围及读者需要调整的实践]

### 验证与遗留
- [实际检查、观察与尚未核实的部分]
```

### C2 · 决定发布时同步版本号

- [ ] README.md、维护/README.md 与 mkdocs.yml 的默认版本 / 页脚同步 bump；PDF 页眉由构建脚本带入
- [ ] CHANGELOG 里的对应条目

### C3 · 同步 frontmatter

- [ ] 被修改的章节 `updated:` 字段改成今天
- [ ] 仅改动正文的文件更新日期；没有修改 README 正文时不单独刷新日期

### C4 · 提交前检查范围（如果用 git）

确认差异、验证结果与提交范围，再按协作流程提交。工作区中可能还有其他修订，不能默认把所有改动一并纳入本次维护。

## Part D · 事件触发：不把重要变化拖到下个季度

有工作范式或核心假设变化的线索时，按[审查专篇](范式与理念审查.md)登记并分诊：

- 已确认的错误、危险建议或失效前提：及时修订或加注范围，并同步相关内容。
- 有潜在重大影响但未核实：在 Unreleased 记录待验证项，安排资料、反证或实验。
- 不影响当前建议：记录观察理由与再次检查的条件，可以不改正文。

季度审查集中处理复杂候选，但不是纠错的等待期。版本由修订对读者的实际影响决定，不把所有月度发现都塞进 patch。

## 工具辅助（推荐）

### 自动化脚本（不必须，但值得写一次）

你可以写一个 bash + curl 脚本做 A1 的前 3 项——**全部走 Jina Reader 代理**（`r.jina.ai`），避免被原站的 Cloudflare / JS 渲染挡掉：

```bash
#!/bin/bash
# check-month.sh —— 月度检查辅助
# 约定：所有页面探索一律走 https://r.jina.ai/<原 URL>

JINA="https://r.jina.ai"

echo "=== LM Arena ==="
curl -s "$JINA/https://arena.ai/leaderboard" | head -120

echo "=== OpenRouter ==="
curl -s "$JINA/https://openrouter.ai/rankings" | head -80

echo "=== SWE-bench Verified ==="
curl -s "$JINA/https://www.swebench.com/verified.html" | head -80

echo "=== 附录 B 链接存活扫描（通过代理，规避反爬误报） ==="
awk -F'[()]' '/\(http/ {print $2}' 附录/B-参考文献.md | while read url; do
  code=$(curl -s -o /dev/null -w "%{http_code}" "$JINA/$url")
  echo "$code $url"
done
```

> [!TIP]
> Jina Reader 免费额度足够月度用量；如要更高配额或更稳定的吞吐，注册账号拿 API key 后加 `-H "Authorization: Bearer <KEY>"`。书的维护**禁止**把 key commit 进仓库，放 `~/.config/jina/token` 或环境变量。

## 节奏失控时

长时间未维护时，先核对高影响内容：危险操作、数据与权限、退役接口、价格承诺和支撑主线的假设。标注已核验与未核验范围，再按风险安排补查。

间隔多久不直接决定必须发哪个版本，也不足以认定全书已经失效。需要限制读者依赖的具体内容，应就地说明，不能只修改更新时间。
